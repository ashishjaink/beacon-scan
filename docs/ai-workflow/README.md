# AI workflow

This folder is the transparent record the exercise asks for: what was asked of an AI agent, when, and how the work was split between Ashish and Claude. It's meant to be read alongside `docs/decisions-during-build.md`, which is where the model logged judgment calls it made along the way instead of guessing silently.

## Contents

- **`README.md`** — this file: the workflow split, and the reflection below.
- **`WO-BEACON-01.md`** — a verbatim copy of the work order issued at the repo root, the single document that defines scope, hard rules, and every lane's prompt.
- **`prompts-log.md`** — every prompt given to an agent, in order, appended by that agent itself as its first action and closed out with a short report as its last. Nothing is reconstructed after the fact; each lane wrote its own entry while it worked.
- **`transcripts/`** — full session exports: the orchestrator's own conversation and all four lane subagents' transcripts, exported by the same Claude Code session via its own export tool (see below for why this isn't the split the work order originally described).

## How the work was split

| Who / what | Did |
|---|---|
| **Ashish** | Wrote the take-home brief into a PRD, made every numbered decision in `docs/PRD.md §5` (D1–D13), approved running each stage (the store pick was flagged but not explicitly re-confirmed — see `docs/decisions-during-build.md` D-01 — everything downstream ran on his explicit go-ahead: "git init ... run the real scan", "commit this", the full second-day continuation), chose to skip the Loom video rather than have it faked, and owns the submission itself. |
| **Cowork planning session** | Where the PRD, the OpenSpec change (`openspec/changes/beacon-mvp/`), and the work order (`WO-BEACON-01.md`) got written and locked, before any code existed. |
| **Claude Code — Lane 0** | Verified the store shortlist against PRD §6's criteria, scaffolded the repo, froze the type contracts, recorded fixtures, wrote the hand-made sample findings Lane C builds against. |
| **Claude Code — Lanes A/B/C/D (parallel)** | Collector, scoring engine, report + CLI, and this documentation set, each working only in its own file paths against the frozen contracts, offline from fixtures. |
| **Claude Code — Lane I / orchestrator** | Integration, both real (online) scans, the `beacon diff` run between them, the git init and every commit, the PDF and transcript export, and the final submission packaging — all done directly by the orchestrating session rather than a fresh Lane I subagent, once it became clear the same session already held full context from reviewing every lane's output. |

The instinct behind the split: anything that's a judgment call about the product, the store, or the voice stays with Ashish. Anything that's mechanical once the contracts are frozen — implementing a spec, running formulas, writing HTML from a template — goes to a lane working in isolation against those contracts, so four lanes can run at once without stepping on each other. What changed from the original plan is scope, not that instinct: Ashish delegated the mechanical *execution* of later steps (the real scans, `git init`, commits, packaging) that the work order had originally marked `[Ashish]`, once he'd reviewed and approved the pipeline producing them — the judgment calls inside those steps (how to fix a real bug, what to name a commit, what belongs in the final zip) still went through the same log-and-keep-moving discipline as everything else here, not silent autonomy.

**No separate "Cowork planning session" transcript exists in `transcripts/`.** The work order's own text (and the row above) describes a Cowork session for PRD/OpenSpec/WO authoring, distinct from the Claude Code session(s) executing it. In this repo's actual history, one continuous Claude Code session did both the orchestration described in the WO *and* everything after it — there was no separate planning session to export. If a genuinely separate planning transcript exists outside this repo, it belongs here too, but it wasn't part of what this session could export.

## Reflection

What got delegated: writing the OpenSpec change and the work order itself, scaffolding the repo, running four lanes in parallel against disjoint file sets, drafting all three essays from Ashish's own theses (`docs/theses.md`), and — after Ashish reviewed the first pass and explicitly asked for it — the mechanical execution of everything from that point forward: both real scans, git operations, PDF/transcript export, and final packaging. The theses — the actual opinions, the architecture, the defensibility verdict — are Ashish's; drafting them into essay prose with the voice rules applied is delegated, and the final voice pass (removing the `DRAFT` comments) is still his to do.

What stayed human, even inside a broad delegation: the store pick still needed sign-off (flagged prominently rather than assumed silent); the theses themselves; the final essay voice; anything the work order marks non-negotiable (no runtime LLM, no API keys, scores as indices never currency); and the one thing this session flatly could not do regardless of instruction — record a Loom video. Told to "do all the recording etc. things yourself," the honest answer was that no video/audio capability exists in this environment, not a workaround or a placeholder pretending otherwise; Ashish chose to skip it rather than have it faked. A model asked to do something outside its actual capability should say so plainly and let the human decide, not simulate compliance.

What went wrong and got corrected, in the open rather than silently, across both days:
- **D-01** (Lane 0): the PRD's literal "≥30% multi-option variants" store-selection criterion isn't met by any real candidate store, including both fallbacks — reinterpreted against what the criterion is actually *for* (a signal for the size-curve check), full reasoning and raw numbers logged rather than quietly picking a store that looked compliant on paper.
- **D-02** (Lane 0): `bluetokaicoffee.com`'s `robots.txt` blocks `/policies/*` for every bot, which the original type contract couldn't represent without either lying (`false` = confirmed missing, when it's actually just unchecked) or silently dropping the distinction — fixed in the schema before any lane built against it.
- **D-10, D-11** (second day, first real online scan): the collector had never been run against a *live* store with 225 real collections before — it hit a genuine 429 storm the retry logic couldn't recover from (a concurrency bug: one request backing off from a 429 didn't stop its sibling from still hammering the server) and a hard crash when one specific product page turned out to be individually disallowed by robots.txt. Both are the kind of bug that offline fixtures, by construction, cannot surface — fixed, logged, and the same real scan re-run successfully afterward rather than declared "done" on the offline result alone.
- **D-13** (second day): `npm test` was intermittently flaky — not because of the two days' worth of real product code, but because running all 5 test files in parallel made a couple of intentionally-real-timer-based tests race against CPU contention from the other files' worker threads. Found by actually re-running the suite multiple times rather than accepting one green run, root-caused instead of just raising a timeout, and fixed by disabling file-level parallelism.

The common thread: every one of these is a case where the honest move was to say what was actually true — a criterion nobody could meet, a claim the collector couldn't back up, a bug that only a live store would expose, a test suite that wasn't as green as it looked, a video that couldn't be made — and log it, rather than pick the answer that made the run look cleaner than it was.

Where the transcript lives: `prompts-log.md` in this folder has the full prompt for every lane, appended by that lane as its own first action, so the record isn't reconstructed after the fact — plus a final entry from the orchestrator's second-day continuation. `docs/decisions-during-build.md` has every deviation, each attributed and timestamped, including the second day's real-scan bug fixes. `transcripts/` has the raw session exports, described above.
